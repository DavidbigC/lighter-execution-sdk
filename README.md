# Lighter Execution SDK

An unofficial Rust library for signing and submitting orders on Lighter Main and Lighter Robinhood. Each client binds the REST endpoint, WebSocket endpoint, and L2 signing domain to its selected network. Orders use integer market ticks to preserve the caller's price and size.

| Network | L2 signing domain |
| --- | ---: |
| `Network::Main` | `304` |
| `Network::Robinhood` | `466324` |

## Install

Add this to your project's `Cargo.toml`.

```toml
[dependencies]
lighter-execution-sdk = { git = "https://github.com/DavidbigC/lighter-execution-sdk.git", tag = "v0.2.0" }
```

## Usage

This example signs an IOC limit order locally. The key is a public test fixture. Set market IDs and ticks using the selected deployment's market metadata.

```rust
use lighter_execution_sdk::{LimitOrder, Network, Side, Signer, TimeInForce};

fn main() -> Result<(), lighter_execution_sdk::Error> {
    let signer = Signer::new(Network::Robinhood, 41, 3, &format!("01{}", "00".repeat(39)))?;
    let order = LimitOrder {
        market_id: 1,
        side: Side::Buy,
        size_ticks: 1000,
        price_ticks: 750_000,
        time_in_force: TimeInForce::Ioc,
        reduce_only: false,
        client_order_index: 123,
    };
    let signed = signer.sign_order(&order, 17, 1_800_000_000_000)?;
    assert_eq!(signed.tx_type(), 14);
    Ok(())
}
```

For execution, construct `Client::new(signer)?` with your own signer and call `client.place_order(&order).await?` inside a Tokio runtime. The SDK also exposes `cancel_order(market_id, index)`, `cancel_all()`, and `warm_nonce()`. A receipt confirms the venue accepted the submission. Check order or fill state separately.

With the `websocket` Cargo feature enabled, `Client::new(signer)?.with_websocket()` prefers a persistent WebSocket. Call `warm_websocket()` inside the runtime to start connecting before the first order. REST is used while the socket is disconnected.

## Nonces and submission outcomes

Share one client per network, account, and API key across tasks. Allocate separate API keys to independent writers. Each client sends its transactions sequentially and caches the next nonce after an acknowledgment.

A WebSocket submission with no conclusive reply is replayed over REST with the same signed transaction and nonce. If the outcome remains unclear, the client reports `Error::Unknown` and holds subsequent operations on that key. Use the transaction hash from the error to reconcile against the venue before calling `resume_after_reconciliation(nonce, &tx_hash)`. Version 0.2 requires both the nonce and hash so a delayed recovery call can only clear the transaction it verified. Cancelling a submission future can leave the same unresolved state. Keep track of your client order indices to reconcile uncertain results.

## Verification

```sh
cargo test --locked
cargo test --locked --all-features
```

This crate reuses the daemon's unaudited signing implementation. The test suite uses synthetic keys and loopback HTTP and WebSocket servers. It checks order and cancellation signatures against hashes generated by the official Go SDK for both networks. See [attribution](THIRD-PARTY-NOTICES.md) for source provenance.
